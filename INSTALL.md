# Инструкция простыми словами

Как поставить Armbian (Linux) на приставку **H96 Max RK3528** вместо Android.

Читать можно с любого места: если что-то непонятно — внизу есть словарь терминов.

---

## Что вообще происходит

Приставка — это маленький компьютер. Внутри стоит процессор Rockchip RK3528, память,
флеш-память (eMMC) и модуль Wi-Fi/Bluetooth. Заводская система — Android для телевизора.
Мы её заменяем на Linux (Armbian) — получается маленький сервер или мини-компьютер.

Есть **два пути**. Выбирай любой, они приводят к одному результату.

| Путь | Кому подходит | Время |
|---|---|---|
| **А. Готовый образ** | не хочется ничего настраивать | 15–20 минут |
| **Б. С нуля** | хочется разобраться или сделать своё | 40–60 минут |

---

## Словарь терминов

Если в тексте встретится незнакомое слово — смотри здесь.

| Слово | Что это значит |
|---|---|
| **Образ** (`.img`) | файл, внутри которого целиком лежит система: как «слепок» диска. Его записывают на флешку |
| **Прошить** | записать образ на флешку или во внутреннюю память приставки |
| **eMMC** | внутренняя флеш-память приставки (как жёсткий диск в компьютере). У нас 32 ГБ |
| **microSD / USB-флешка** | внешний носитель, с него делаем первый запуск. На этой приставке надёжен **USB**, а слот microSD может не работать |
| **DTB** (device tree) | «описание железа» для Linux: где какой чип, какие пины, какие частоты. Если описание неверное — что-то не работает (у нас так было с Wi-Fi) |
| **Maskrom** | аварийный режим восстановления приставки. Как «режим прошивки» у телефона — включается кнопкой и перемычкой |
| **idbloader** | самый первый загрузчик, крошечная программа, которая запускает всё остальное |
| **sha256** | контрольная сумма файла — длинный набор букв и цифр. Если после скачивания она совпала, файл не побился при передаче |
| **dd** | команда в Linux, которая копирует файл «байт в байт». Ей записывают образ на флешку |
| **SSH** | способ управлять приставкой с компьютера по сети, через чёрное окно терминала |
| **root** | главный пользователь в Linux (администратор) |
| **armbian-config** | программа-настройщик в Armbian: меню, где можно поставить рабочий стол, настроить сеть и т.п. |
| **Docker** | способ запускать программы в «контейнерах», не устанавливая их в систему |

## Путь А. Готовый образ (самый простой)

В репозитории уже лежит образ, где всё настроено: Wi-Fi, Bluetooth, видео-ускоритель,
HDMI. **Рабочего стола в нём нет** — это серверная версия. Если понадобится графика,
поставишь одной командой (шаг А4).

### А1. Скачать образ

Со страницы релиза:
https://github.com/superromchik1/h96max-rk3528-armbian/releases/latest

Файл называется `h96max-rk3528-armbian.img.gz`, весит 862 МБ.

### А2. Проверить, что файл не побился

Это необязательно, но полезно: сравни `sha256` скачанного файла с тем, что указан
в описании релиза. Должно быть:

```
cfc377aecdef62c189ab19da3cae239b36b5d9216e3374f78ae9aa34f8174edd
```

Как проверить в Windows (PowerShell):

```powershell
Get-FileHash .\h96max-rk3528-armbian.img.gz -Algorithm SHA256
```

Если набор букв совпал — всё хорошо.

### А3. Записать образ на флешку

Нужна флешка на 8 ГБ или больше. **Всё, что на ней было, сотрётся.**

- **Windows:** программа [Rufus](https://rufus.ie) или [balenaEtcher](https://etcher.balena.io).
  Выбери файл `.img.gz` и флешку → «Записать».
- **Linux:** одна команда (где `/dev/sdX` — твоя флешка, проверь внимательно!):

  ```bash
  gunzip -c h96max-rk3528-armbian.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
  ```

### А4. Первый запуск

1. Выключи приставку из розетки.
2. Вставь флешку **в USB-порт**.
3. Подключи HDMI к телевизору и USB-клавиатуру.
4. Включи питание.

> **Важно про носитель.** Загружаться лучше **с USB-флешки**. Слот microSD на этой
> приставке работает нестабильно: карта может не определиться или система с неё
> не стартует. Если образ записан на microSD и приставка не грузится — перезапиши
> тот же образ на обычную USB-флешку, этого достаточно. **Если microSD не идёт —
> значит только USB.**

Через 20–40 секунд появится либо логотип Armbian, либо чёрный экран с текстом — это нормально.
Логин: `root`, пароль: `1234`. Система сразу попросит придумать новый пароль — придумай и запиши.

> Если вместо Linux загрузился Android — значит приставка не увидела флешку.
> Попробуй другой USB-порт (лучше USB 2.0, чёрный, а не синий) или другую флешку.

**Рабочий стол** (если нужен):

```bash
armbian-desktop-install
```

Это поставит лёгкий рабочий стол LXQt. Если хочешь другой — `armbian-desktop-install xfce`,
`... mate`, `... cinnamon`, `... kde`.

Готово. Дальше — сразу к разделу «Как проверить».

## Путь Б. Установка с нуля

Нужно, если хочешь собрать своё или поставить на уже работающую систему.

### Б0. Что понадобится

- приставка H96 Max RK3528 (4/32, плата `RK3528_DDR3_8X4_V12`) — на других ревизиях не проверялось;
- **USB-флешка на 8 ГБ** — основной вариант (см. примечание ниже);
- microSD — как запасной вариант, если USB-порта нет под рукой;
- HDMI-телевизор и USB-клавиатура;
- кабель **USB-A ↔ USB-A** — только на случай, если что-то пойдёт не так (для восстановления);
- компьютер с Windows или Linux.

> **Про носитель.** Загрузка проверена **с USB-флешки**. Слот microSD на этой приставке
> работает нестабильно — карта может не определиться или система с неё не стартует.
> Если записал на microSD и не грузится — перезапиши образ на USB-флешку,
> этого достаточно. **Если microSD не идёт, значит только USB.**

### Б1. Скачать образ Armbian

Берём «чистый» Armbian для плат на rk3528 — его собирает проект **ophub**:

https://github.com/ophub/amlogic-s9xxx-armbian/releases

Нужен файл вида `Armbian_*_rockchip_h96-max-m2_bookworm_*_server_*.img.gz`
(раздел Rockchip, ищи `rk3528`).

### Б2. Записать на флешку

Так же, как в шаге А3: Rufus на Windows или `dd` на Linux.

### Б3. Первая загрузка

1. Выключи приставку, вставь **USB-флешку** (если используешь microSD и не грузится — перезапиши на USB),
   подключи HDMI и клавиатуру, включи питание.
2. Логин `root`, пароль `1234`.

> Если грузится Android, нужно один раз нажать кнопку восстановления при включении.
> На этой плате — зажать кнопку внутри гнезда AV (или зажать Reset зубочисткой).

### Б4. Установить систему во внутреннюю память (по желанию)

Можно оставить систему на флешке, но лучше перенести на eMMC — быстрее и надёжнее.

```bash
armbian-install
```

В меню выбери:
- «Install/Update the bootloader on eMMC» — ставит загрузчик;
- «Install/Update Armbian to eMMC» — переносит систему;
- файловая система — `ext4`.

После этого выключи питание, **вынь флешку**, включи снова — система загрузится уже с eMMC.

> Важно: не оставляй флешку в приставке при загрузке, если на ней копия системы.
> Два одинаковых раздела сбивают загрузку с толку.

### Б5. Применить «фиксы» — главный шаг

Фиксы — это правки, без которых Wi-Fi и Bluetooth не работают. Они лежат в репозитории
в виде скрипта, который делает всё сам.

1. Скопируй папку с файлами на приставку (например, через флешку или `scp`).
2. Выполни:

```bash
cd /root/h96max-setup        # или где лежит папка
chmod +x setup-h96max-rk3528.sh
./setup-h96max-rk3528.sh
```

Скрипт спросит, нужен ли рабочий стол. Если запускать с ключом — не спросит:

```bash
./setup-h96max-rk3528.sh --no-desktop      # сервер, без графики
./setup-h96max-rk3528.sh --desktop=lxqt    # с рабочим столом LXQt
```

Другие рабочие столы: `--desktop=xfce`, `--desktop=mate`, `--desktop=cinnamon`, `--desktop=kde`.

Скрипт сам:
- поправит DTB (описание железа) и сохранит копию старого рядом;
- прописнет нужный DTB в загрузчике;
- настроит драйвер Wi-Fi;
- поставит правила, чтобы видео-ускоритель был доступен обычному пользователю;
- настроит автозапуск Bluetooth.

### Б6. Перезагрузка

```bash
reboot
```

## Как проверить, что всё работает

Подожди после загрузки 30 секунд и выполни по очереди.

**Wi-Fi** — список сетей и подключение:

```bash
nmcli dev wifi list
nmcli dev wifi connect "ИМЯ_СЕТИ" password "ПАРОЛЬ"
```

Ожидаемо: в списке видны сети и 2.4, и 5 ГГц; после подключения появляется `wlan0`.

**Bluetooth**:

```bash
bluetoothctl show
bluetoothctl scan on
```

Ожидаемо: есть адрес вида `xx:xx:xx:xx:xx:xx` (у каждого свой) и строка `Powered: yes`,
а `scan on` показывает соседние устройства (наушники, колонки, телефоны).

**Видео-ускоритель (GPU)**:

```bash
glxinfo -B | grep renderer
```

Ожидаемо: `Mali450`.

**HDMI**:

```bash
cat /sys/class/drm/card0-HDMI-A-1/status
```

Ожидаемо: `connected`.

**Ethernet** (если воткнут кабель):

```bash
ethtool end0 | grep -E 'Speed|Supported link modes'
```

Ожидаемо: скорость `100Mb/s` (или 10/100 в списке поддерживаемых).
Гигабита на этой плате не будет: контроллер `gmac0` у RK3528 работает только
по RMII, а это максимум 100 Мбит. На других ревизиях платы с внешним RGMII-PHY
бывает 1 Гбит — но там другое железо.

```bash
# Home Assistant — умный дом
curl -fsSL https://get.docker.com | sh
docker run -d --name hass --restart=unless-stopped --net=host \
  -v /opt/hass:/config ghcr.io/home-assistant/home-assistant:stable

# Klipper — управление 3D-принтером
sudo apt install git -y
git clone https://github.com/th33xitus/kiauh.git
./kiauh/kiauh.sh
```

**Если нужна графика:**

```bash
armbian-desktop-install            # LXQt — самый лёгкий
armbian-desktop-install xfce       # XFCE
armbian-desktop-install kde        # KDE Plasma
armbian-desktop-install mate       # MATE
armbian-desktop-install cinnamon   # Cinnamon
```

Или меню: `armbian-config` → System → Desktop.

**DNS** (если «интернет есть, а имена не резолвятся»):

```bash
resolvectl status | head -20        # какие серверы реально используются
resolvectl query github.com         # проверка резолва
```

Установщик настраивает DNS правильно: явные серверы (1.1.1.1, 8.8.8.8), запасные
(9.9.9.9, 149.112.112.112), кэш включён, а `/etc/resolv.conf` — ссылка на
stub-резолвер `127.0.0.53`. Если понадобится свой DNS:

```bash
nmcli connection modify "ИМЯ_СЕТИ" ipv4.dns "192.168.1.1 1.1.1.1"
nmcli connection up "ИМЯ_СЕТИ"
```

## Обновление системы — и почему правки не потеряются

Обновлять систему можно как обычно:

```bash
apt update && apt upgrade
# или через armbian-config / armbian-update
```

Есть один риск: обновление ядра может заменить файл описания железа (DTB) в `/boot`
на стоковый — тогда Wi-Fi, Bluetooth, GPU и HDMI перестанут работать. Хуже всего,
что внешне система загрузится, и непонятно, что случилось.

Поэтому при установке ставится **h96max-dtb-guard** — маленькая «страховка», которая:

1. при каждой загрузке смотрит, что DTB на месте и пропатчен;
2. если DTB заменили — заново применяет правки (с резервной копией);
3. если DTB удалили — восстанавливает из `/usr/local/share/h96max/`;
4. проверяет `fdtfile` и `console=display` в `armbianEnv.txt`;
5. запускается и после установки пакетов — так ловится обновление ядра.

Проверить состояние вручную:

```bash
h96max-dtb-guard.sh check
# "Итог: всё в порядке" и код 0 — хорошо
# "Итог: есть проблемы" и код 1 — запустите h96max-dtb-guard.sh (без check)
```

Посмотреть, что guard делал:

```bash
journalctl -t h96max-dtb-guard -n 30
cat /var/log/h96max-dtb-guard.log
```

> Совет: ветку ядра лучше не менять (6.1 → 6.18). Guard вернёт DTB, но драйверы
> в mainline-ядрах другие, и Wi-Fi/видеодекодер могут не подняться.

## Если что-то сломалось — восстановление

Приставку почти невозможно «убить»: есть аварийный режим **Maskrom**.
Он работает, даже если система вообще не запускается.

### Где взять всё нужное

| Что | Ссылка |
|---|---|
| Фото и описание, как войти в Maskrom на этой плате | [тема на 4PDA, сообщение 142893859](https://4pda.to/forum/index.php?showtopic=1076564&view=findpost&p=142893859) |
| **RKDevelopTool** (консольная утилита, Windows) | [RKDevelopTool_v1.37.zip](https://dl2.radxa.com/tools/windows/RKDevelopTool_v1.37.zip) |
| **RKDevTool** (то же, но с графическим интерфейсом) | [RKDevTool_Release_v3.37.zip](https://dl2.radxa.com/tools/windows/RKDevTool_Release_v3.37.zip) |
| Драйверы USB для приставки (нужны один раз) | [DriverAssitant_v5.14.zip](https://dl2.radxa.com/tools/windows/DriverAssitant_v5.14.zip) |
| Rufus (запись образа на флешку, Windows) | [rufus.ie](https://rufus.ie) |
| balenaEtcher (альтернатива Rufus) | [balena.io/etcher](https://etcher.balena.io) |

> Всё это лежит в открытом каталоге Radxa: https://dl2.radxa.com/tools/windows/
> (там же есть другие версии инструментов).

### Шаг 1. Войти в Maskrom

1. Отключи питание.
2. Зажми кнопку внутри гнезда AV и замкни две площадки на плате — они рядом
   с флеш-памятью. Подробно с фото: [4PDA, сообщение 142893859](https://4pda.to/forum/index.php?showtopic=1076564&view=findpost&p=142893859).
3. Подключи кабель USB-A↔USB-A к компьютеру.
4. Приставка определится как устройство `Loader` или `Maskrom`
   (в диспетчере устройств — `Rockusb Device`, `VID 2207`).

Если компьютер не видит приставку — поставь драйверы `DriverAssitant`, они нужны один раз.

### Шаг 2. Записать образ

**Вариант с графическим интерфейсом (RKDevTool):**

1. Запусти `RKDevTool.exe`.
2. Внизу должно быть `Found One MASKROM Device` (или `Loader`).
3. Вкладка **Advanced** → выбери файл образа → **Write**.
4. Дождись `Success`, нажми **Reset Device**.

**Вариант с командной строкой (RKDevelopTool):**

```powershell
# 1. проверить, что приставка видна
RKDevelopTool.exe ld

# 2. записать образ с нулевого сектора
RKDevelopTool.exe wl 0 h96max-rk3528-armbian.img

# 3. перезагрузить
RKDevelopTool.exe rd
```

> Образ перед записью нужно распаковать: `h96max-rk3528-armbian.img.gz` → `.img`.
> На Windows это делает 7-Zip или `gzip -d`.

### Шаг 3. Если не грузится загрузчик

Бывает, что образ записан, а система не стартует: тогда нужно отдельно восстановить
загрузчик (idbloader) — первые 4 МиБ образа, начиная со смещения `0x8000`.
В образе он уже есть, просто извлеки его:

```bash
# Linux / macOS / Git Bash
dd if=h96max-rk3528-armbian.img of=idbloader.bin bs=512 skip=64 count=8000
```

Затем запиши его по смещению `0x8000` (сектор 64):

```powershell
RKDevelopTool.exe wl 64 idbloader.bin
RKDevelopTool.exe rd
```

После перезагрузки система должна подняться с eMMC.

## Частые проблемы

| Что видно | Что это значит | Что делать |
|---|---|---|
| Чёрный экран, нет изображения | в DTB остался мусор от Android | скрипт должен был его убрать; проверь, что в `/boot/armbianEnv.txt` строка `fdtfile=rockchip/rk3528-evb2-ddr3-v10.dtb` |
| `lima: get bus clk failed -2` в логах | правки GPU не применились | запусти скрипт ещё раз и перезагрузись |
| Wi-Fi: `tx msg fc retry fail` | не включено питание модуля (3.3 В) | DTB не пропатчен — запусти скрипт |
| Bluetooth: адрес `00:00:00:00:00:00` | подключается не тем способом | нужен `btattach`, а не `hciattach`; и он должен стартовать после загрузки BT-прошивки |
| Нет звука по HDMI | выбран не тот выход | `aplay -l`, затем `alsamixer` |
| Не грузится с eMMC | загрузчик не на месте | восстанови idbloader через Maskrom (шаг 3 выше) |

## Что лежит в репозитории

```
README.md                      — общее описание проекта
INSTALL.md                     — этот файл
setup-h96max-rk3528.sh         — главный установщик (делает все правки)
make-image.sh                  — сборка такого же образа из любого Armbian
scripts/dtb-fix.py             — правки описания железа (DTB)
scripts/dtb-guard.sh           — страховка: возвращает правки после обновления ядра
scripts/dtb-guard.service      — запуск страховки при загрузке
scripts/apt-dtb-guard.conf     — запуск страховки после установки пакетов
scripts/resolved-dns.conf      — настройки DNS (systemd-resolved)
scripts/btattach.service       — автозапуск Bluetooth
scripts/bt-init.sh             — включение Bluetooth после загрузки
files/rk3528-evb2-ddr3-v10.dtb — уже пропатченный DTB (можно скопировать вручную)
```

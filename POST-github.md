# Armbian на H96 Max RK3528: Wi-Fi, Bluetooth и GPU теперь работают

Несколько дней разбирался с дешёвой приставкой **H96 Max RK3528 (4/32, плата `RK3528_DDR3_8X4_V12`)** и довёл её до полностью рабочего Armbian: Wi-Fi, Bluetooth, GPU, HDMI — всё живое, загрузка с eMMC. Делюсь результатом и граблями, потому что в интернете по этой плате почти ничего нет.

Всю техническую часть — чтение `dmesg`, правки device tree, сборку драйверов и проверки на живой системе — делал в связке с **DeepSeek Harness** (агентная среда DeepSeek): я ставил задачи и смотрел на телевизор, агент работал по SSH. Первый подобный опыт — и он оказался рабочим.

## Что было сломано и почему

**1. HDMI не работал.** Вендорский DTB тащил за собой `chosen/bootargs` от Android (`init=/init`, `drm_kms_helper.fbdev_emulation=0`) — ядро поднимало DRM, но не выводило картинку. Лечится вычищением узла `chosen/bootargs`.

**2. Wi-Fi (AIC8800D80) перечислялся, но не работал.** В логах бесконечно `aicwf_sdio_tx_msg: tx msg fc retry fail`. Причина оказалась не в драйвере и не в прошивках: пин `gpio4.4`, описанный в DTB как «reset SDIO», на этой плате включает **силовой регулятор 3.3 В** модуля. Пока он не поднят как `regulator-fixed`, чип не может принять прошивку.

**3. GPU Mali-450 не запускался.** `lima: get bus clk failed -2` — драйвер ждёт клоки `bus`/`core`, а в вендорском дереве они называются `clk_mali`/`aclk_gpu_mali`/`pclk_gpu`. После правки имён: `glxinfo` → `Mali450`, отрисовка 600 кадров 1080p ускорилась с 24,4 с до 1,7 с.

**4. Bluetooth молчал.** Две причины: узел `bluetooth-platdata` был `status = "disabled"`, и `hciattach` для этого чипа не подходит — работает только `btattach -B /dev/ttyS2 -S 1500000 -P h4`, причём строго **после** загрузки BT-прошивки (`aicbsp: BT firmware ready`, ~16-я секунда). Плюс `hci0` приходит soft-blocked — нужен `rfkill unblock`.

**5. Аппаратный декодер `rkvdec2` не инициализировался** — не хватало клоков `clk_core`/`clk_cabac` (драйвер ждёт их, а в DTB были `aclk_vcodec`/`clk_hevc_cabac`). Теперь probe проходит, MPP декодирует 1080p на 132 fps.

## Как повторить

Два пути:

**1. Готовый образ** (сервер, без графики):

```
h96max-rk3528-armbian.img.gz   (862 МБ)
sha256: f728d5c6ce3ed3420e616b8ef855b0ca0ed280806aec2a808cb0950e215852f4
```

Прошить через `dd`/Rufus/Etcher — и всё работает сразу.

**2. Установщик** на свежем Armbian:

```bash
git clone <repo> h96max && cd h96max
./setup-h96max-rk3528.sh                  # спросит про рабочий стол
./setup-h96max-rk3528.sh --no-desktop     # сервер
./setup-h96max-rk3528.sh --desktop=xfce   # или lxqt, kde, mate, cinnamon
```

Скрипт правит DTB (с бэкапом), настраивает драйвер Wi-Fi, ставит udev-правила для VPU, поднимает Bluetooth-сервисы и спрашивает, нужен ли рабочий стол. По умолчанию — **без него**: большинству эта коробка нужна как сервер (Home Assistant, Klipper, Docker).

Рабочий стол при желании — любой: LXQt, XFCE, MATE, Cinnamon или KDE Plasma
(и через `armbian-desktop-install`, и через `armbian-config`, и обычным `apt`).

Подробная инструкция с нуля (включая Maskrom-восстановление): `INSTALL.md`.

## Что пока не получилось

Честно, чтобы не было ложных ожиданий:

- **Аппаратное декодирование в пользовательских плеерах.** VPU работает, но `rkmpp`-обвязка ffmpeg (проверил 5.1 и 6.1) несовместима с MPP 1.1.0 на этом ядре — декодер отдаёт 3–4 кадра и встаёт с `MPP_ERR_BUFFER_FULL`. Программно 1080p идёт с запасом (105 fps), 4K — на грани (~28 fps).
- **Браузер не использует GPU для композитинга:** Mali-450 = OpenGL 2.1, а WebRender требует 3.1.

## Кому это может пригодиться

Тем, кто купил такую приставку под сервер: 4 ядра A53, 4 ГБ RAM, eMMC, 100 Мбит Ethernet, полностью пассивное охлаждение (под 100% нагрузкой 70 °C, троттлинга нет). За свои деньги — отличный Home Assistant / Klipper / Docker-хост.

Если у вас другая ревизия платы (4/64, DDR4, другой Wi-Fi-чип) — правки могут отличаться, но подход тот же: сверяйте `dmesg` с тем, что описано в README.

Буду рад, если кто-то поможет добить MPP: нужен либо патч `rkmpp`-декодера ffmpeg под новый API MPP, либо версия MPP из того же SDK, что и ядро ophub (`mpp_service` от 14.10.2026).
